# xl 诊断码与 `xl check`

> 本文是 **诊断码表的唯一事实来源**：每个码的级别、触发条件、报错位置与修复建议都在这里。
> 检查的对象是 [`xl-syntax.md`](./xl-syntax.md)（下称「语法」）定义的 `*.xl.md`；命令行接口见 [`xl-cli.md`](./xl-cli.md)；ts 产物映射见 [`xl-emit-ts.md`](./xl-emit-ts.md)；完整输入与期望产物见 [`xl-base-case.md`](./xl-base-case.md)。

> `xl check` **永不联网、永不调用 harness**：只做语法 / 结构 / 引用的静态检查，耗时毫秒级。

---

## 1. 命令

```text
xl check [paths...] [options]
```

| 分组 | 选项 | 作用 |
| --- | --- | --- |
| 目标 | `-t, --target <lang>` | 按目标语言检查「生成依据是否齐备」，可重复；缺省 `ts`（决定 `W3010` / `W3011` 提示的是哪一种目标语言） |
| 判定 | `--strict` | warning 视为 error（退出码 1） |
| 判定 | `--max-warnings <n>` | warning 超过 n 条即失败（缺省不限） |
| 过滤 | `--ignore <codes>` | 忽略指定规则码，逗号分隔，如 `--ignore W3011,E1107` |
| 输出 | `--format <fmt>` | `pretty`（缺省）\| `compact` \| `json` |
| 输出 | `--json` | NDJSON 诊断流（等价 `--format json`） |
| 输出 | `--color <when>` | `auto`（缺省）\| `always` \| `never`；另受 `NO_COLOR` / `FORCE_COLOR` 影响 |
| 全局 | `--cwd <dir>` | 以指定目录为基准解析路径与配置 |
| 全局 | `-q, --quiet` | 只输出 error |
| 全局 | `--verbose` | 额外输出检查文件数、被忽略的规则码与耗时 |
| 全局 | `-h, --help` / `-v, --version` | 帮助 / 版本 |

* 输入解析与 `build` 完全一致（`xl-cli.md` §3.2）：文件 / 目录 / glob 展开，排除 `node_modules`、`.git`、`dist`、`build` 与 `.xlignore`，永不把产物（首行含 `@generated by xl`）当输入。
* 规则码来自 `xl.json` 的 `check.ignore` 与 `--ignore` 的并集；被忽略的码不参与 `--strict` 与 `--max-warnings` 计数，`--verbose` 下打印「ignored N×<code>」。
* `build` 在生成前隐式跑一遍 check（对应 `xl-cli.md` §3.2 的「先解析并校验」；关掉它用 §5 里的 `--no-check`）；**有 error 立即终止**，退出码 1。

### 1.1 退出码

| 码 | 条件 |
| --- | --- |
| 0 | 无 error（允许 warning；`--strict` 下不允许） |
| 1 | 至少 1 个 error；或 `--strict` 且有 warning；或 warning 数超过 `--max-warnings` |
| 2 | 用法错误：路径不存在（`E0001`）、没有匹配到 `*.xl.md`（`E0002`）、非法 `--target`（`E0003`）、未声明的自定义目标（`E0004`） |

### 1.2 严重级别

| 级别 | 语义 |
| --- | --- |
| `error` | 语法 / 结构非法，产物无法确定；`build` 会因此终止 |
| `warning` | 合法但会削弱生成质量（缺说明、缺语言指示、跨文件重名等）；`build` 只提示 |

> **码段与级别解耦**：`E` / `W` 前缀只表示码的归属段（`E0` 输入、`E1` 语法与结构、`E2` 产物、`E4` harness），个别码的**级别**由本表决定而非前缀——如 `E1105` / `E1107` 是以 `E` 段编号的 warning，`E2003` 同此。判定退出码时一律以本表列出的「级别」为准。

## 2. 诊断格式

**pretty**（缺省）：三到四行一组，含源码行与 `^` 下划线：

```text
<path>:<line>:<col>: <severity>[<code>]: <message>
  <source line>
  ^^^^^^^^^^^^
  help: <修复建议>
```

示例（第三段为单行摘录，`help:` 行只在有修复建议时出现）：

````console
$ xl check pkg/demo.xl.md
pkg/demo.xl.md:105:3: error[E1302]: default body must use the default language 'ts', got 'js'
  ```js
  ^^^^^^
  help: 把默认语言块的围栏改成 'ts'；或放进 `### csharp` 之类的语言子标题下

pkg/demo.xl.md:142:3: warning[W3010]: member 'tick' has no ts body and no '### csharp' hint
  ## method tick:()=>int
  ^^^^^^^^^^^^^^^^^^^^^^
  help: 补一个 ts 默认语言代码块，或加 `### csharp` 指示

pkg/demo.xl.md:73:1: error[E1202]: modifier 'readonly' is not valid on property
  ## readonly property ORIGIN:string
````

**compact**：每行一条诊断，无源码片段与 help：

```text
<path>:<line>:<col>: <severity>[<code>]: <message>
```

**json**（`--format json` / `--json`）：NDJSON，`ev` 是事件名。

| `ev` | 字段 |
| --- | --- |
| `diag` | `file` `line` `col` `severity` `code` `msg`，可选 `help` `endLine` `endCol` |
| `check.end` | `ok` `files` `errors` `warnings` `ms` |

```json
{"ev":"diag","file":"pkg/demo.xl.md","line":105,"col":3,"severity":"error","code":"E1302","msg":"default body must use the default language 'ts', got 'js'","help":"把默认语言块的围栏改成 'ts'"}
{"ev":"check.end","ok":false,"files":2,"errors":1,"warnings":3,"ms":14}
```

* 诊断**稳定排序**：`文件 → 行 → 列 → 规则码`；同一处被解析器与检查器各报一次时（同文件、同码、同起始位置、消息等价）只保留 span 最大的一条。
* 路径一律相对 `--cwd`、POSIX 分隔符（`pkg/demo.xl.md`），保证跨平台输出可比。

## 3. 规则码表

### 3.1 `E0xxx` 输入与文件层

| 码 | 级别 | 规则 | 位置 | help |
| --- | --- | --- | --- | --- |
| `E0001` | error | 显式给出的输入路径不存在 | 该路径 1:1 | 检查路径拼写，或省略 `paths` 让 xl 递归当前目录 |
| `E0002` | error | 展开后没有匹配到任何 `*.xl.md` | 1:1 | 指定文件 / 目录 / glob，或确认后缀是 `.xl.md` |
| `E0003` | error | `--target` 非法（既不是内置语言，也不是 `xl.json` 的 `targets.<lang>`） | 1:1 | 用 `xl targets` 查看已知目标 |
| `E0004` | error | 自定义目标缺少 `targets.<lang>.ext` | `xl.json` 键位置 | 在 `xl.json` 补 `"targets": { "<lang>": { "ext": ".kt" } }` |
| `E0005` | error | 非 UTF-8、带 BOM，或含 `CRLF`（源文件要求 UTF-8 无 BOM、LF） | 文件首个违规位置 | 另存为 UTF-8（无 BOM）+ LF 换行 |

> `E0001`–`E0004` 属于**用法错误**（退出码 2），不进诊断计数；`E0005` 属于文件内容错误（退出码 1）。

### 3.2 `E1xxx` 语法与结构层

**A. 文件层 —— 骨架与段落**

| 码 | 级别 | 规则 | 触发示例 | help |
| --- | --- | --- | --- | --- |
| `E1001` | error | 文件为空，或只有空白 / 只有散文，没有任何标题 | 空 `*.xl.md` | 写 `# namespace` 或直接写一级声明 |
| `E1002` | error | 未知一级段落种类（合法：`dependencies` / `namespace` / `type` / `const` / `method` / `enum` / `interface` / `class` / `statement`） | `# struct point` | 换成合法关键字，见语法 §2 |
| `E1003` | error | `# namespace` 名字缺失或非法 | `# namespace` / `# namespace 9a` | 名字用小写标识符，如 `# namespace demo` |
| `E1004` | error | `# dependencies` 不是第一个段落（语法 §0：必须第一个、至多一次） | `# namespace demo` 之后又出现 `# dependencies` | 把 `# dependencies` 移到文件最前面 |
| `E1005` | error | 段落或成员顺序非法（模块级声明必须排在类型声明之前；`### get` / `### set` 必须紧跟其 `property`） | 模块级 `# method` 出现在 `# class` 之后；`### get` 挂在 `## field` 下 | 按语法 §0 的骨架重排：`dependencies → namespace → 模块级声明 → 类型声明` |
| `E1006` | error | `# dependencies` 的 `xl` 代码块行非法：不是 `import { … } from "./x.xl.md"`、目标是 `*.xl.md` 之外的路径、目标不存在、或导入名在目标文件中没有对应的一级声明 | `import { nope } from "./util.xl.md"` | 检查相对路径与导出名；依赖文件本身不参与构建，但必须可解析 |

**B. 声明层**

| 码 | 级别 | 规则 | 触发示例 | help |
| --- | --- | --- | --- | --- |
| `E1101` | error | `enum` / `interface` / `class` 名字缺失或非法 | `# class` / `# interface 2fa` | 名字用小写标识符（与产物 `export class point` 一致） |
| `E1102` | error | `# interface` 出现 `implements`，或它的成员带初始值 / 函数体 | `# interface a implements b` | interface 只描述签名；实现放到 `# class` |
| `E1103` | error | 泛型参数非法：形态不是 `<T>` / `<T extends X>` / `<K extends string, V = any>` | `# class c<T extends>` | 每个参数写成 `名字 [extends 约束] [= 默认值]` |
| `E1104` | error | `extends` 目标在本次检查范围内不存在（含类、接口、泛型约束里的类型） | `# class box extends pointt` | 补声明，或修正拼写 |
| `E1105` | warning | `implements` 目标不是 `interface`，或类未实现其全部成员（成员名或参数个数不一致） | `# class box implements marker` 且 `marker` 是 class | 让目标成为 `# interface`，并补齐 `print(): string` 之类的成员 |
| `E1106` | error | 同一文件内一级声明重名 | 两个 `# class point` | 改名；同一源文件内符号必须唯一 |
| `E1107` | warning | 跨文件同名一级类型（同一次检查范围内） | `pkg/a.xl.md` 与 `pkg/b.xl.md` 都有 `point` | 改名为 `aPoint` / `bPoint`，避免产物撞名 |
| `E1108` | error | `# type` 缺少 `= <原文>` | `# type MemberKind` | 写成 `# type MemberKind = "field" \| "method"` |
| `E1109` | error | `# enum` 没有 `- case` 成员，或成员重名 | 两个 `- case red` | 删除重复项，或补 `- case <name>` |
| `E1110` | error | `# statement` 既没有非空的默认语言（ts）块，也没有任何带代码块的 `## <lang>` 段（语法 §17） | 光秃秃的 `# statement` | 补一个 `ts` 默认语言代码块，或加 `## <lang>` 段；没有正文的语句段没有任何生成依据 |

**C. 成员层**

| 码 | 级别 | 规则 | 触发示例 | help |
| --- | --- | --- | --- | --- |
| `E1201` | error | 未知成员种类（合法：`field` / `property` / `method` / `constructor`） | `## attr x:int` | 换成合法关键字，见语法 §2 |
| `E1202` | error | 修饰符非法或组合非法 | `constructor` 带 `static` / `readonly` / `async`；`readonly` 用在 `property` / `method`；interface 成员带 `private` / `protected`；`# protected` 一级声明；`# statement` 带任意修饰符；枚举成员带修饰符 | 只保留该成员种类允许的修饰符（语法 §3、§8、§12–§15、§17） |
| `E1203` | error | 成员名字缺失或非法，或 `# statement` 后面多写了名字 | `## field :int = 0` / `# statement entry` | 补合法标识符名字；`# statement` 是匿名段，关键字后面什么都不写 |
| `E1204` | error | 类型标注非法：括号 / 尖括号不配对、未知类型名、`?` 写在非成员 / 非参数位置 | `## field x:Array<int` / `## method m:()=>Foo` | 检查类型写法，见语法 §6、§8、§12 |
| `E1205` | error | 同一类型内成员重名（含 `property` 展开后的访问器名与同名字段冲突） | 两个 `## field x:int` | 改名 |
| `E1206` | error | `constructor` 重复，或返回值不是 `void` | `## constructor:(x:int)=>int` / 两个 `constructor` | 返回类型固定 `void`，一个类至多一个 |
| `E1207` | error | 初始值与声明类型明显不符 | `## field x:int = "0"` / `## field flag:bool = 3` | 改正初始值或类型标注 |
| `E1208` | error | 参数非法：缺名字、缺类型、括号不配对、可选参数 `?` 排在必选参数之后、默认值写在 `?` 参数上 | `# method m:(a:int, b?)=>void` | 写成 `(a:int, b?:int)`，必选参数在前 |
| `E1209` | error | `property` 既无 `### get` 也无 `### set`，或 `### get` / `### set` 出现在非 `property` 成员下 | `## property label:string` 后没有访问器 | 补 `### get` / `### set`，或把它改成 `## field` |
| `E1210` | error | `### get` / `### set` 重复，或 `### set` 排在 `### get` 之前 | 两个 `### get` | 每个访问器至多一次，顺序固定 get → set |
| `E1211` | error | 同一处写了多个可见性修饰符（`public` / `protected` / `private` 互斥，至多一个） | `## public private field x:int = 0` | 只保留一个 |
| `E1212` | error | 枚举成员行非法：不是 `- case <name>` 形态 | `- red` / `- case` / `- case green =` | 写成 `- case <name>` 或 `- case <name> = <原文>`（语法 §9） |

**D. 代码块与语言覆盖层**

| 码 | 级别 | 规则 | 触发示例 | help |
| --- | --- | --- | --- | --- |
| `E1301` | error | 一个成员下出现多个默认语言（`ts`）代码块 | 同一个 `## method` 下两个 `ts` 围栏块 | 合并成一个默认语言块，其余改用 `### <lang>` 子标题 |
| `E1302` | error | 代码围栏的语言未知，或默认语言块的围栏不是 `ts` | 成员体用 `js` 围栏 | 把默认语言块的围栏改成 `ts`；或放进 `### csharp` 之类的语言子标题下 |
| `E1303` | error | 同一父标题下 `### <lang>` / `## <lang>` / `#### <lang>` 语言名重复 | 同一个 `## method` 下两个 `### csharp` | 合并同类语言段 |
| `E1304` | error | `interface` 成员带函数体（接口只描述签名） | `# interface p` 的 `## method print:()=>string` 下带 `ts` 代码块 | 删除函数体，或改用 `# class` |
| `E1305` | error | 未知的 `###` 子标题：既不是 `get` / `set`，也不是语言名 | `## method m:()=>void` 下的 `### note` | 改成 `### get` / `### set`（仅在 `property` 下）或 `### <lang>`；说明散文直接写在成员标题下 |

### 3.3 `W3xxx` 生成质量提示（warning）

| 码 | 级别 | 规则 | help |
| --- | --- | --- | --- |
| `W3010` | warning | 可执行成员（类 / 接口外的 `method`、`constructor`、`property` 的 get / set、带初始值的 `field`、`# statement`）既无默认语言（ts）代码块，也无 `### <target>` / `## <target>` 指示（提示语言由 `--target` 决定，缺省 `ts`）；`# statement` 没有默认语言块时，目标里含 `ts` 也报——那一段会从 ts 产物里整段消失 | 补一个 `ts` 默认语言代码块，或加 `### csharp` / `## csharp` 指示 |
| `W3011` | warning | `### <lang>` / `## <lang>` 只有说明文字、没有代码块——合法但生成信息量低 | 补该语言的代码块，或删掉空壳子标题 |
| `W3012` | warning | 代码块为空（围栏之间只有空白） | 补内容，或删除该代码块 |
| `W3013` | warning | `# statement` 的默认语言块里出现静态顶层 `import`（或带 `from` 的 `export`）：它会被提升到产物头之前（语法 §17） | 把依赖写进 `# dependencies`（语法 §4），默认语言块里只留可执行语句 |
| `W3101` | warning | 目标语言的覆盖段引用了 ts 侧依赖（如 `_`、`fetch`、`File.ReadAllText` 对应的 `rf`）但 `# dependencies` 里没有对应说明 | 在 `# dependencies` 的 `## <lang>` 段说明该依赖的来源 |
| `W3102` | warning | 成员说明（标题下的散文）为空 | 补一句用途说明：它会进 harness prompt，并成为产出代码注释 |
| `W3103` | warning | `# namespace` 的说明为空 | 补包用途说明，供 harness 通道使用 |
| `W3104` | warning | `xl.json` 的 `build.target` / `targets` 声明的某个目标语言，在文件里没有任何对应覆盖段 | 只为确实需要人工指示的目标补 `## <lang>` 段；不需要时用 `--ignore W3104` |

> `W3010`–`W3012` 是「块层」提示，`W3101`–`W3104` 是「语义层」提示；两者都只影响 harness 通道的生成质量，不影响 ts 直出。

## 4. 覆盖范围与不检查的内容

| 项 | 说明 |
| --- | --- |
| `# type` 右侧 | 是**原文**，不参与类型解析（语法 §6），因此不检查其内部语法 |
| `- case green = 2` 右侧 | 同上，按目标语言直译 |
| 默认语言块内部 | **不做代码语义检查**：`ts` 块只被当作字符串包装进产物，语法错误由使用方的 `tsc` / 编辑器暴露 |
| `### <lang>` 块内部 | 同上，且它只进 prompt |
| harness 通道产物 | 由 `--verify` 的结构回读校验负责（`xl-cli.md` §3.4），不属于 `xl check` |
| 依赖文件 | 只被解析以支撑 `E1006` / `E1104` / `E1107`；依赖文件自身的诊断**不会**出现在本次输出里（它只有在被显式列为输入时才会被检查） |

## 5. `build` 期间的诊断

`xl build` 复用同一份码表（§3），另外在产物层与 harness 通道报以下码：

| 码 | 级别 | 触发 | help |
| --- | --- | --- | --- |
| `E2001` | error | 输出冲突：同一产物路径被计划写多次（`--flat` 压平或跨源文件撞名），或目标位置已存在非 xl 产物且未给 `--force` | 去掉 `--flat`、改名，或加 `--force`；xl 绝不静默覆盖 |
| `E2002` | error | 写盘失败（目录不可写、磁盘满、路径被占用） | 检查 `--out` 权限与磁盘状态 |
| `E2003` | warning | 目标产物存在 xl 头但指纹不匹配（被手工改过），即将被覆盖；`--dry-run` 时只提示 | 不要手改产物；改动写回 `*.xl.md` |
| `E4001` | error | harness 失败：非 0 退出、超时、空答案，或 `--retries` 退避重试耗尽 | 用 `--verbose` 查看 harness 命令与 stderr；核对 `harness.env` 与 profile |
| `E4002` | error | 结构回读校验（`--verify`）不通过：产物的类型集合 / 成员名集合 / 参数个数与 IR 不一致 | 收敛 prompt 上下文（补 `## <lang>` 指示），或放宽该目标的校验 |

* 退出码：`E2001` / `E2002` 为 1；`E2003` 只提示；`E4001` / `E4002` 为 3，`--keep-going` 下部分文件失败为 4（`xl-cli.md` §3.8）。未声明扩展名的自定义目标在参数解析阶段就被 `E0004` 拦下（退出码 2）。
* 一个文件失败不影响其它文件，也不影响已成功产物的写入。

## 6. 抑制与配置

```jsonc
{
  "check": {
    "ignore": ["W3011", "W3104"],
    "strict": false,
    "maxWarnings": null
  }
}
```

| 手段 | 作用 |
| --- | --- |
| `--ignore <codes>` | 本次忽略指定规则码（不参与计数） |
| `check.ignore` | 配置文件里持久忽略 |
| `--strict` / `check.strict` | warning 提升为失败 |
| `--max-warnings <n>` / `check.maxWarnings` | warning 数量上限 |

* 行内抑制**不存在**：xl 不支持 `// xl-ignore` 之类的注释——注释放进默认语言块会被原样带进产物。需要豁免时用 `--ignore` / `check.ignore`，或直接修正源文件。
* `--quiet` 只影响 pretty 输出，不影响退出码与 `--json` 的事件流。

```console
$ xl check .
✖ 3 errors, 4 warnings in 2 files (14ms)

$ xl check . --strict --format compact
pkg/a.xl.md:12:3: warning[W3010]: member 'tick' has no ts body and no '### csharp' hint
✖ 3 errors, 5 warnings in 2 files (13ms)
```
